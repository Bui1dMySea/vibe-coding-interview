# 批改搜索vibe coding面试

## 背景

拍照搜题链路里有一条捷径：用户拍照搜题时，先查历史高质题库（库 id `8889` / `8899`），召回的候选经过**三个阶段**处理后输出最终结果：

1. **阶段一（召回过滤）**：按质量规则过滤召回候选
2. **阶段二（粗排截断）**：粗排打分后全局取 topN，控制进精排的量
3. **阶段三（精排后路由）**：只保留「相同题」通道的候选，按精排分数取 topK

目录里的 `recall_filter.py` 是一份 **AI 生成的初版实现**（入口 `run_pipeline.py`，数据 `mock_input.json`）。

## 数据说明

`mock_input.json` 含 5 个 query，每个 query 的 `query_res` 是 `{库id: [候选, ...]}`。粗排分数已预置在候选的 `pre_ranking_score` 字段（真实链路中由粗排模型产生）。候选项字段：


| 字段                  | 含义                                              |
| ------------------- | ----------------------------------------------- |
| `score`             | 召回向量相似度                                         |
| `is_same`           | 历史同题复用标注（int，可能为 0/1/2）                         |
| `api_id`            | 召回接口 id（**可能是 int 也可能是 str**）                   |
| `pre_ranking_score` | 粗排分数（预置）                                        |
| `is_same_vl`        | 精排通道判定，取值 `"相同"` / `"相似"` / 可能缺失                |
| `ranker_score`      | 精排分数，**两种格式并存：`0.88` 或 `[[0.88]]`**，也可能为 `null` |


## 要求

### 阶段一 `filter_recall_stage`

- 只对目标库 `8889` / `8899` 生效；**其他库原样透传，不做任何过滤**
- 目标库中，一个候选必须**同时**满足以下条件才保留：
  - `score >= 0.90`
  - `is_same != 1`
  - `api_id` 不在 `{777}` 中
- 过滤后每个目标库按 `score` 降序保留最多 20 条

### 阶段二 `truncate_prerank`

- **全局展平所有库**的候选，按 `pre_ranking_score` 降序，取 topN 后重组为 `{库id: [...]}`
- 本考核中 N=5（入口脚本已传参）

### 阶段三 `filter_postrank`

- 只保留 `is_same_vl == "相同"` 的候选
- 按 `ranker_score` 降序取 topK（本考核 K=5）；`ranker_score` 缺失/无法解析视为 -inf 排末位
- **没有任何"相同"候选时返回 `[]`**（表示 fallback 走解题链路）
- `question_type` / `thresholds` 是**预留参数，本次不实现**。产品侧后续计划按题型加阈值过滤（仅供了解，**不要写进代码**）：
  
  | 题型  | 阈值               |
  | --- | ---------------- |
  | 填空题 | 4.1              |
  | 选择题 | 4.0              |
  | 解答题 | 4.3              |
  | 判断题 | 不启用（强制 fallback） |
