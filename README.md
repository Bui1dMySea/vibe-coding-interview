# 批改搜索 vibe coding 面试

## 背景

拍照搜题线上链路（简化后给你考的这一截）：

1. **ES + VL 双路召回已经完成**。每道题给你的 `general` 里是召回截断后的 **20 条**，不要再设计召回。
2. **粗排**：控制进精排的量。
3. **精排**：把进精排的候选拆成两个列表。主路相同题列表为空时，才重走历史高质库 `8889` / `8899`。

目录里的 `recall_filter.py` 是一份 **AI 生成的初版**（入口 `run_pipeline.py`，数据 `mock_input.json`）。

## 你的任务

**禁止把整道题一次性丢给 agent「帮我做完」。** 可以用 AI 写某一段、查某一种格式，但拆阶段、定规则、读题判断哪条像同一道题、验证输出，必须是你自己的思考。整包转发、自己讲不清为什么，视为未完成。

1. 让 pipeline 跑通：`python3 run_pipeline.py`
2. 对照下面的要求，核对实现，**修复所有与要求不符的地方**
3. 用你认为可靠的方式**证明**修对了（材料请保留）
4. 产出：修好的 `recall_filter.py`、重新生成的 `output.json`、验证材料。**保持** `recall_filter.py` 文件名与 `filter_recall_stage` / `truncate_prerank` / `filter_postrank` 三个函数名不变

> 时间 **30 分钟**。可以用 AI，但不能代替你拆问题和做判断。

## 数据说明

`mock_input.json` 含 5 个 query。每个有 `query_text`（用户题干）和 `query_res`：

| 桶 | 含义 |
| --- | --- |
| `general` | ES+VL 多通道召回后的 20 条 |
| `8889` / `8899` | 历史高质库，**仅当主路精排没有可用相同时才用** |

候选项字段：

| 字段 | 含义 |
| --- | --- |
| `content` | 候选题干（文本） |
| `channel` | `vl` / `es` / `both` |
| `score_vl` / `score_es` / `rrf_score` | 各通道召回分（可能为空） |
| `pre_ranking_score` | 粗排分（预置） |
| `is_same_vl` | 大模型判别通道，取值 `"相同"` / `"相似"` / 可能缺失 |
| `confidence` | 大模型认为是相同的程度，可能缺失 |

`is_same_vl` 和 `confidence` 是大模型判别生成的字段，属于重要特征，其中 `confidence` 表示大模型认为是相同的程度。注意：大模型判断可能存在噪声，需要添加限定条件来尽可能避免噪声级联。

正例要靠读题干和链路规则自己判断，题包不会标出哪几条是正例。

## 核心目标

1. **粗排**：进入精排的 5 条里，包含相同题的比例尽可能高。
2. **精排**：输出两个列表 `[相同题列表]`、`[相似题列表]`。相同题列表允许为空，表示当前没有相同题；但不应漏掉真相同题，也不能把真相同题放进相似题列表。

## 要求

### 进粗排前 `filter_recall_stage`

这 20 条已经是召回结果。本层**不要再按库名过滤 8889/8899**（它们不是脏召回，是后手高质库）。需要的话只做你认为必要的脏数据清理，并说明理由。

### 粗排 `truncate_prerank`

- 只对当前这一路截断：先主路 `general`，主路相同题列表为空才对 `8889`/`8899` 截断。
- 取 topN（入口已传 N=5）再按桶重组。截断依据自己定，目标是进精排的 5 条里相同题尽量多。`pre_ranking_score` 只是特征之一。

### 精排 `filter_postrank`

- 返回 `(相同题列表, 相似题列表)`。相同题列表可以为 `[]`。
- 结合 `is_same_vl` 与 `confidence` 并自己加限定，避免噪声级联：不要漏真相同，不要把真相同放进相似列表。
- 主路相同题列表为空时走 `8889`/`8899`；仍然为空则保持空列表（后续解题）。
- `question_type` / `thresholds` 预留，**不要按题型阈值表写进代码**。

入口脚本先跑主路；相同题列表为空再把历史库送进同一套粗排+精排。
